03 — Selected work

Three problems worth explaining.

All open source. Code linked on every entry.

  1. 01 Open source

    Long-Running Autonomous Agent

    A self-hosted AI agent that keeps working autonomously for days or weeks at a time, rather than for a single conversation.

    Role
    Sole author — architecture, implementation, docs.
    Problem
    Long-horizon agents drift off task and hallucinate steps, and a crashed process usually means starting the whole run again.
    Approach
    An LLM-driven planning loop with explicit, inspectable plan state; sandboxed Python execution for tool use; persistent memory across steps; and resumable sessions controlled through an API surface.
    Outcome
    Runs unattended over multi-day horizons, structured planning keeps hallucinated steps down, and interrupted sessions resume instead of restarting.
    • Python
    • LangChain
    • LLMs
    • FastAPI
    Source
  2. 02 Open source

    ai-cache

    A Python library that transparently caches LLM responses across OpenAI, Anthropic Claude and Google Gemini.

    Role
    Sole author — library design, provider adapters, release.
    Problem
    Iterating on prompts re-sends near-identical requests all day. Every repeat costs money and adds seconds of latency, and each provider SDK caches differently — or not at all.
    Approach
    One caching layer behind a single interface, keyed on request content, so switching providers doesn't change caller code.
    Outcome
    Repeat calls resolve locally instead of over the network, cutting spend and latency on SQL and NLP query workloads. Published as an installable package.
    • Python
    • OpenAI
    • Anthropic
    • Gemini
    Source
  3. 03 Open source

    Agent Testing Suite

    An evaluation dashboard that makes multi-agent pipelines legible — where time goes, where money goes, which tools actually get called.

    Role
    Sole author — instrumentation and dashboard.
    Problem
    Multi-agent systems are opaque. When a pipeline is slow or expensive, there's rarely evidence pointing at which agent or tool call is responsible.
    Approach
    Instrument each run for latency, API cost and tool-call frequency, then render the pipeline as an interactive flow so bottlenecks are visible rather than guessed at.
    Outcome
    Turns agent tuning into a data-driven exercise: regressions show up as numbers, and optimisation targets the step that's actually costing.
    • Python
    • Multi-agent
    • LangChain
    • Streamlit
    Source
